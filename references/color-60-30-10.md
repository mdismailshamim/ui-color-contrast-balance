## 1. Role definitions and area budgeting

| Role | Target | Tolerance | Where it lives |
|---|---|---|---|
| Dominant | 60% | 55-70% | page background, large panels, body text color |
| Secondary | 30% | 20-35% | cards, sidebars, nav, form fields, section bands, borders |
| Accent | 10% | 5-12% (hero band may reach 15%) | primary CTA, active tab, key number, link, focus, one illustration color |

Budgeting method:
1. List every surface on the screen. Assign each to dominant, secondary, or accent.
2. Estimate area. If accent > 12%, demote some accent uses to secondary (outline buttons, tinted chips).
3. If secondary < 20%, the page is probably flat: add surfaces or section bands.
4. Text is judged separately for contrast, but its color belongs to the dominant family.

Context shifts (break the ratio on purpose):

| Context | Suggested split | Why |
|---|---|---|
| Data-dense dashboard | 70 / 25 / 5 | Accent reserved for status and the primary action |
| Marketing hero band | 50 / 30 / 20 | One loud moment, rest of the page returns to 60/30/10 |
| Editorial / luxury | 75 / 20 / 5 | Restraint signals quality |
| Kids / playful | 50 / 30 / 20 with 2 accents | Only if the brand asks for it |
| Forms / checkout | 65 / 30 / 5 | Calm, single CTA |

## 2. Building a palette from one brand color

1. Take the brand hue as the accent. Convert to OKLCH if possible (`oklch(L C H)`).
2. **Accent shades:** 50, 100, ..., 900. Use L ≈ 0.97 (50) down to 0.25 (900). Pick one shade for button fill (usually 600-700), a darker shade (700-800) for accent-as-text on light backgrounds, a lighter shade (300-400) for accent-as-text on dark backgrounds.
3. **Neutrals:** 9-11 steps tinted toward the brand hue: chroma 0.005-0.02, same hue as the accent (or its complement for warm brands). Light mode: bg = step 50, surface = white or 100, border = 400-500, muted text = 600-700, text = 900-950.
4. **Semantic hues:** red/green/amber/blue at L ≈ 0.45-0.55 for light mode text, L ≈ 0.75-0.85 for dark mode text.
5. **Verify pairs** with the script. Adjust lightness, not hue, until every pair passes.

Rules for brand colors that fail:
- Light brand color (yellow, light green, orange) cannot carry white text. Use dark text on the brand fill (`on-accent` = near-black) and a darker derived shade for text/links.
- Mid-tone brand color (many teals/oranges around 3-4:1 with white) usually needs one step darker for button fill, or switch `on-accent` to near-black.

## 4. Token mapping

CSS variables with automatic dark mode:

```css
:root{
  color-scheme: light dark;
  --bg:#F8FAFC; --surface:#FFFFFF; --surface-alt:#E2E8F0;
  --text:#0F172A; --muted:#475569; --border:#64748B;
  --accent:#1D4ED8; --on-accent:#FFFFFF; --focus:#1D4ED8;
  --error:#B91C1C; --success:#15803D; --warning:#92400E;
}
@media (prefers-color-scheme: dark){
  :root{
    --bg:#0B1220; --surface:#131C2E; --surface-alt:#1B2740;
    --text:#E6EDF7; --muted:#9FB0C8; --border:#6B7C96;
    --accent:#60A5FA; --on-accent:#0B1220; --focus:#93C5FD;
    --error:#FCA5A5; --success:#86EFAC; --warning:#FCD34D;
  }
}
:focus-visible{ outline:3px solid var(--focus); outline-offset:2px; }
```

Tailwind: map the same names in `theme.extend.colors` to `var(--token)` so components read `bg-bg text-text` and never raw hex.

Figma: collection `color` with modes `Light` and `Dark`; groups `bg`, `surface`, `text`, `accent`, `border`, `state`. Bind every fill/stroke to a variable. Name by role, not by hue (`accent/default`, not `blue-600`).

Three-layer token model for larger systems: primitive (`blue-600`) → semantic (`accent`) → component (`button-primary-bg`). Components only touch the component layer.

## 5. Dark mode rules

| Rule | Detail |
|---|---|
| No pure black/white pairing | Use tinted `#0B1220`-style bg and `#E6EDF7`-style text to avoid halation |
| Elevation = lighter | Base bg darkest; each elevated surface +3-6% lightness (cards, menus, modals) |
| Desaturate accents | Raise lightness, lower chroma ~10-25% versus the light-mode accent |
| `on-accent` flips | Usually near-black on a light accent fill |
| Re-run every pair | Muted text, borders, and focus ring are the usual failures |
| Shadows weaken | Use border/surface-step for separation instead of shadows |
| Images | Reduce brightness slightly or add a subtle overlay so photos do not glare |

Pick dark/light from the *physical context of use* (night dashboard, bright outdoor mobile, long reading) rather than as a default, and always ship a real dark theme if you offer one rather than inverting.

## 6. Semantic colors

- Each state needs: text color (≥ 4.5:1 on its surface), an optional tinted background, an icon, and a text label. Color is never the only signal.
- Semantic fills for badges: pick the tint (e.g. L 0.95) and the text (L 0.40) as a *pair* and run the script on that pair.
- Info/link blue may be the accent; do not introduce a second blue for "info".
- Limit semantic color area to a few percent. A screen that is half red is an error state, not a design.

## 7. Color-blind and non-color cues

About 8% of men have a color-vision deficiency. Rules:
1. Pair status color with an icon and a word.
2. In charts use direct labels, markers, dashes, or patterns in addition to hue.
3. Differ in **lightness**, not only hue (red vs green at similar lightness collapse for many users).
4. Inline links inside body text need an underline (or a ≥ 3:1 contrast against surrounding text plus a non-color cue on hover/focus).
5. Test with a simulator (Figma plugins, browser dev tools "Emulate vision deficiencies") and with a grayscale screenshot: if hierarchy survives in grayscale, it is robust.

## 8. Common failure modes

| Failure | Fix |
|---|---|
| Accent button text fails (white on yellow/orange) | Dark `on-accent`, or darker accent fill |
| Muted text `#9CA3AF` on white (2.5:1) | `#6B7280` (4.8:1) or `#4B5563` (7.6:1) |
| Border `#E5E7EB` on white for inputs (1.2:1) | Input border ≥ 3:1, e.g. `#6B7280`; keep light dividers for decoration only |
| Accent used everywhere | Demote to outline/ghost; keep one filled CTA per view |
| Gradient text/button | Measure at the worst stop; or use solid fill |
| Dark mode reuses light accent | Re-pick accent for dark (lighter, less saturated) |
| Hover state darker/lighter than allowed | Treat hover/active/disabled/visited as extra pairs |
